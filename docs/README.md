### 牌局引擎核心（Plan 4a / 4b，无独立计划文档）

主牌次序与墩赢家判定已实现于 `src/shengji/engine/`，见设计文档 §7.3 与 §7.6。

| 模块 | 内容 |
|---|---|
| `engine/trump.py` | 主牌判定、牌力次序（**含正级/副级**）、比较、排序、主牌集合枚举 |
| `engine/trick.py` | 结构判定（单张/对子/拖拉机/甩牌）、墩赢家、分牌点数 |
| `engine/accounting.py` | 变体规则表、已知集合、未见牌池、未知底牌堆、不变式 I1/I2 |

**已实现并验证**：单张、对子、拖拉机结构；主牌压副牌；强弱相等先出者赢；
非领出花色且非主牌者不能赢；分牌点数统计；记账模型的三类重复扣减缺陷全部有回归测试。

**明确未实现**：**甩牌（一次出多张杂牌）的赢家判定**。
完整规则需判断甩牌合法性（是否均为该花色最大）与各家跟牌的结构匹配，
规则复杂且地区差异大。当前实现保守地让领出方赢，但返回 `confident=False`，
由上层走人工确认流程 —— 与设计文档 §9.1「宁可让你点一下，也不静默算错」一致。

**未验证变体拒绝启动**：`(6, 3)` 的手牌数/底牌张数标注为 `UNVERIFIED`，
`get_variant_rule` 遇到它会抛错，而不是采用猜测值。

**待实测确认**（设计文档 §7.6.3）：副级三门之间是否可互相比较。
默认实现为「同级、不可互压」，该差异直接影响墩赢家与分牌归属。

### 记账模型修正的三个缺陷

`engine/accounting.py` 对应设计评审抓出的最严重问题，每个缺陷都有回归测试：

| 缺陷 | 后果 | 修正 | 回归测试 |
|---|---|---|---|
| 快照时点混用 | 扣底后的 H 与扣底前的 P 有交集（`P − D`），重复扣减 | 统一采用扣底后 `(H, D)`，构造时断言互斥 | `test_declarer_known_set_rejects_overlap` |
| `played ∩ known` | 自己打出的牌已在 known 中，再扣会让未见池变负 | 只对「来自 known 之外」的牌扣减 | `test_own_play_does_not_decrement_unseen` |
| 底牌不属于任何一家 | 计数约束把底牌派给某家，破坏 `certain ⊆ ground_truth` | 显式保留容量受限未知堆 `bottom_unknown` | `test_bottom_unknown_is_reserved_so_invariants_hold` |

## 实测证据（`spike/`）

设计中的每个常量都来自这些脚本的实测输出，改常量前请先重跑复核。

| 脚本 | 测什么 | 关键结论 |
|---|---|---|
| `bench_capture.py` | mss 与纯计算成本 | mss 整屏 17.7ms；absdiff 0.019ms |
| `bench_capture2.py` | dxcam 与模板匹配 | 模板匹配 0.145ms/次 |
| `bench_decisive2.py` | dxcam 增量语义 | 无变化时 `grab()` 返回 `None`，0.038ms |
| `bench_truth.py` | **交叉验证** | dxcam 46.7 FPS 与 mss 地面真值 46.3 Hz 吻合 → 不丢帧 |
| `analyze_screenshots*.py` | 四区真实布局 | 十字四宫格；1 张牌 56px、2 张 72px |
| `analyze_felt_threshold.py` | 桌面色能否定位牌桌 | **不能** —— 背景与桌面同色 |
| `analyze_card_blobs.py` | 牌尺寸块筛选 | 面积是区分牌块与同形 UI 元素的唯一特征 |

**踩坑记录**：早期一次测量得出「dxcam 只有 12 FPS」，是**测量方法缺陷**
（用 `latest_frame_ticks` 计数）造成的假象。后经 mss 地面真值交叉验证推翻。
结论一律以交叉验证版本为准。
