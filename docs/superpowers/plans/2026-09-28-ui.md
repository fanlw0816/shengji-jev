# UI 层 Implementation Plan（含实施记录）

> **状态：🟡 显示/热键/穿透已完成并验证；交互式纠正面板未做。**
>
> 代码位置：`src/shengji/ui/`、`src/shengji/session.py`、`src/shengji/tools/run_counter.py`

**Goal:** 一个半透明置顶小窗，实时显示剩余牌、各家分数、墩次与待确认提示，
**默认鼠标穿透不干扰游戏**，需要纠正时用全局热键切到交互模式。

**Architecture:** 刻意分为两层 —— **纯逻辑**（`session` 会话状态、`viewmodel` 视图构建、
`hotkeys` 解析）与 **Qt 部件**（`overlay` 渲染、`app` 编排）。
纯逻辑层完整单测；Qt 层在 offscreen 平台下断言渲染内容与窗口行为。

**Tech Stack:** Python 3.13, PySide6 6.11, pytest-qt

---

## 分层理由

GUI 难测，但"事件 → 状态 → 该显示什么文本"这条链路完全可以纯单测。
因此所有业务判断都在纯逻辑层，Qt 部件只负责把字符串画出来。

| 层 | 文件 | 可测性 |
|---|---|---|
| 会话状态 | `session.py` | 纯单测，与 Qt 无关 |
| 视图构建 | `ui/viewmodel.py` | 纯函数，纯单测 |
| 热键解析 | `ui/hotkeys.py` | 纯函数，纯单测 |
| 热键注册 | `ui/hotkeys.py` | 需交互式桌面，只测降级路径 |
| 悬浮窗 | `ui/overlay.py` | pytest-qt + offscreen，断言标签内容与窗口标志 |
| 编排 | `ui/app.py` | 注入假后端，`tick_once()` 确定性驱动 |

## 默认穿透 + 热键切交互

悬浮窗默认 `Qt.WindowTransparentForInput`，不干扰游戏点击；
全局热键 `Ctrl+Alt+L` 切换到交互模式后才能操作。

### ⚠️ 实施中发现并修正的 Qt 缺陷

**`setAttribute(WA_TransparentForMouseEvents, ...)` 会把 `WindowTransparentForInput`
标志重新加回来。** 因此必须**先设属性、后设窗口标志**：

```python
# ✅ 正确顺序
self.setAttribute(Qt.WA_TransparentForMouseEvents, not interactive)
self.setWindowFlags(window_flags(interactive))
```

原实现顺序相反，后果是**鼠标穿透永远关不掉** —— 纠正流程也就永远点不到，
而表面上 `interactive` 属性还是 True，属于典型的**静默失效**。

发现方式：写测试断言 `windowFlags()` 后失败，再用 `spike/_dbg_qt2.py`
对比四种调用顺序实测确认（先属性后标志 → 正确；先标志后属性 → 失效）。

另有两条 Qt 约束记录在案：

- 窗口标志变更后需要 `show()` 才对外生效；未显示过的窗口切换标志，
  `windowFlags()` 可能仍返回旧值
- pytest 需要 `QT_QPA_PLATFORM=offscreen`，已在 `tests/conftest.py` 顶层设置
  （必须早于任何 PySide6 导入）

## 全局热键

| 热键 | 动作 |
|---|---|
| `Ctrl+Alt+L` | 切换交互模式（关闭鼠标穿透） |
| `Ctrl+Alt+O` | 强制重读各出牌区（漏抓时手动补） |
| `Ctrl+Alt+P` | 暂停 / 恢复采集 |

用 `RegisterHotKey` + `PeekMessageW` 轮询，挂在 Qt 定时器上，
避免跨线程消息循环。**注册失败只记录不崩溃**（热键常被其它程序占用）。

### 「强制重读」的语义

清掉各区的周期哈希与判稳计数，让下一次稳定帧**重新触发识别** ——
这样即使内容没变也会被重新读出，而不是被去重逻辑挡住。
这是"漏抓时手动补"的实现方式。

## 暂停不丢帧

`tick_once()` 在暂停时**直接返回、不向采集后端取帧**。
若暂停期间继续消费帧，那些帧会被悄悄吃掉，而用户以为只是在暂停显示。

## 会话状态的两条原则

1. **只消费已确认事件**：待确认项只计数，不污染确定记录
2. **牌未识别时如实标记"分牌未知"**，不猜一个结果

## 启动方式

```bash
uv run python -m shengji.tools.run_counter --trump S2 --templates templates.json
```

不给 `--trump` 时分牌无法判定，只显示张数；不给模板库时只报告张数不认牌 ——
两者都会在启动时明确提示，而不是装作能算。
