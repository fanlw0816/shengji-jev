# 事件层 Implementation Plan（含实施记录）

> **状态：✅ 已实现并验证（264 项测试全绿，其中事件层 54 项）。**
>
> 代码位置：`src/shengji/events/`

**Goal:** 把 60Hz 的帧流变成离散的**出牌事件**，并保证低置信度时**绝不静默丢牌**。

**Architecture:** 五个纯逻辑组件 —— `phash`（内容去重）、`ringbuffer`（回溯重算）、
`pending`（待确认队列）、`pipeline`（区域状态机 + 编排）、`types`（载荷）。
全部可用真实截图离线回放验证，不需要游戏运行。

---

## 为什么需要这一层

抓屏给出的是每秒 60 张图，而牌局需要的是"谁在第几墩出了什么牌"。
两者之间隔着三件事：

1. **时机**：牌只显示几秒，且出现时有动画。必须判断"牌什么时候摆定了"
2. **去重**：同一墩牌在屏幕上停留数秒，期间会多次达到"稳定"。
   不去重会把一手牌反复计入，**从机制上破坏统计**
3. **不漏**：人工纠正往往超过环形缓冲的时长（3 秒），
   若暂停期间停止采集，打出的牌会**彻底消失**

---

## 区域状态机

每区独立：

```
EMPTY ──出现牌──> ENTERING ──连续 8 帧差异<阈值──> SETTLED
                    │  ▲                            │
                    │  └────已摆定后又变化──────────┘
                    │
                    └──出现牌前消失──> EMPTY（重置周期）
```

- **首帧永不算稳定**：刚出现那帧没有前帧可比，若算稳定会把动画中间态当成摆定
- **判稳阈值**：连续 8 帧灰度平均绝对差 < 2.0（60Hz 下约 133ms）
- **只在 SETTLED 做识别**

## 三道防线

### ① pHash 去重

对区缩略灰度图算 dHash（差分哈希）。周期内哈希相同 = 同一次显示，跳过。

关键细节：**清空时重置周期**。否则下一墩出现同样的牌（两副牌下很常见）
会被误判为"同一手牌"而漏计。

### ② 看门狗 → `missed_play`

一次占用周期内出现**第二种内容**（没有经过 EMPTY），说明前一手被下一手覆盖、
来不及读取。此时：
- 记一条 `missed_play` 待确认项
- 仍然产出新的 PlayEvent

测试 `test_content_replaced_without_clearing_raises_missed_play` 固定了这个行为：
`right` 区从"一张"直接变成"两张"（中间没清空）会被识别为漏抓。

### ③ 待确认队列 → 绝不静默丢牌

这是设计文档 §9.1 的核心，也是本层最该讲清楚的部分：

| 设计要点 | 实现 |
|---|---|
| 暂停的是**引擎自动提交**，不是采集 | 状态机与采集继续运行 |
| 事件按 `frame_ts` 有序 | 入队时排序 |
| **证据帧入队即落盘** | 不依赖只有 3 秒的环形缓冲 |
| 未纠正事件是显式条目 | 绝不静默丢弃 |
| `missed_play` 与 `low_confidence` 共用队列 | 仅 `reason` 不同 |

**低置信触发的两个阈值是独立的**，任一不达标即触发（合取式，设计文档 §5.1）：

```
confidence      < min_margin      （每张牌最佳与次佳模板分之差的最小值）
frame_agreement < min_agreement   （跨帧投票一致率）
```

**未确认的出牌不进入本墩的确定记录**，但事件本身必须流出 —— 这样上层既不会用错数据，
也不会丢掉这一手。

### 特例：识别层未启用

`library=None` 时只报告"该区出了几张牌"，不假装认出了牌，
**也不把每一手都塞进待确认队列**（那会淹没队列、让队列失去意义）。

## 墩边界

设计文档 §4.6 观察到"一墩结束时全部 N 区同帧清空"。
实现上用**"全部 N 区回到 EMPTY 且此前有过占用"**作为判据 ——
比"严格同帧"更稳健（客户端若有 1~2 帧的逐区清空也不会误判）。

`TrickEndEvent` 携带本墩已确认的 `plays`，便于上层算分与判定墩赢家。
`trick_index` 在墩结束时递增。

## 模块职责

| 模块 | 做什么 |
|---|---|
| `events/phash.py` | dHash 与汉明距离；默认严格相等（宁可重认，不可漏认） |
| `events/ringbuffer.py` | 定长环形缓冲；按时间窗回溯，供低置信时重算 |
| `events/pending.py` | 有序待确认队列；入队即落盘证据 + JSONL 清单 |
| `events/pipeline.py` | `ZoneTracker` + `EventPipeline`，编排上述组件 |
| `events/types.py` | `ZoneState` / `PlayEvent` / `TrickEndEvent` / `PendingItem` |

### 与 Plan 2 的一处接口调整

`extract_card_patches` 增加了可选参数 `occupancy`，让流水线可以复用
已算好的 `detect_occupied_zones` 结果，避免每帧做两次全图斑点检测。

### 离线回放（用真实截图）

把 4 张不同局面的截图按顺序喂进流水线，断言事件序列：

| 序列 | 期望 |
|---|---|
| `empty` × 20 | 无事件 |
| `others_one` × 20 | 恰好 3 个 PlayEvent（上/左/右），各 1 张；下区保持 EMPTY |
| 接 `empty` × 5 | 1 个 TrickEndEvent，携带 3 个 plays；`trick_index` 递增到 1 |
| 接 `all_two` × 20 | 4 个 PlayEvent，各 2 张，`trick_index == 1` |
| `next_two` × 20 | 仅 1 个 PlayEvent（right，2 张） |
| 开局 `empty` × 30 | 不得凭空报墩结束 |
